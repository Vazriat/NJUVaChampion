## v2.1 相对 v2.0 的变化

### 1. 一人多队 + 活跃战队

原来的规则是「一个人只能在一支战队」，这条限制渗透在申请、邀请、审批、建队四处校验里。现在全部放开，并引入「活跃战队」概念：

- **加入新队不再需要退旧队**。队长邀请你时，不会因为「你已在别的队伍」被拒；你自己申请也一样
- **当前活跃战队**（`users.active_team_id`）决定平台内的默认身份：个人主页展示哪支队、`/teams/my` 返回哪支队
- **切换入口**：用户中心「我的战队」列表、战队列表页顶部的「我的战队」切换条，都支持一键「设为当前」
- **自动兜底**：被踢、主动退队、战队解散导致活跃指针失效时，自动回落到最早加入且仍存续的战队；一支都没有时才置空
- **人才市场放开**：已入队也能申请别的队；对已经加入的队伍，招募帖不再显示「申请加入」按钮；求职帖也不再要求「未加入任何战队」
- **入队审批不再搞连坐**：以前同意入队会把你其它所有待处理申请作废，多队模式下这个行为会误伤，已移除

仍然保留的一条限制：**每人最多创建/拥有一支战队**。`teams.captain_id` 是单值字段，且「我担任队长的战队」接口按单值实现。以队员身份加入的战队数量不设上限。

### 2. 队长可修改战队简介

- 新增 `PUT /api/teams/{id}`，仅队长可调用，简介上限 500 字
- 战队详情页简介标题旁出现「编辑」，点开是内联输入框 + 字数计数 + 保存/取消
- 非队长看不到入口，直接调接口返回 `只有队长可以修改战队简介`
- 战队名涉及唯一性与赛事展示，本次未开放给队长

### 3. 修复：认证材料上传 PNG 失败

反馈是「上传 PNG 就失败」，查下来是四个问题叠在一起：

| 位置 | 问题 | 后果 |
|---|---|---|
| nginx | 三份配置都没写 `client_max_body_size`，走默认 **1MB** | 1.5MB 的 PNG 转 base64 后 2MB，直接 413 |
| 前端 `lib/api.ts` | axios 全局超时 10 秒 | nginx→Next→后端三层转发，手机大图极易超时 |
| 后端 `saveFile` | 文件名写死 `.png` | 传 JPEG 也存成 `.png`，Spring 按后缀返回 `image/png`，Safari 不渲染 |
| 后端 Jackson | 单字符串上限约 20MB | 超大图报 `JSON parse error: String value length exceeds 20000000` |

处理：

- nginx 加 `client_max_body_size 20m`，proxy 读写超时 120s
- **上传前压缩**：≤1.2MB 直传；更大的长边缩到 1600px，先试 PNG，仍超 3MB 转 JPEG 0.85；转码前铺白底，避免 PNG 透明区变黑
- 认证上传超时单独放宽到 120s
- 后端按 data URL 的 MIME + 文件头魔数决定后缀（png/jpg/webp/gif/heic/pdf），base64 改用 MIME 解码器，换行不再抛异常
- 错误提示可读了：413 显示「图片太大，上传被服务器拒绝，请压缩后重试」，无响应显示「上传超时或网络中断」

## 功能清单（v2.1 变化部分）

### 战队
- 一人可加入多支战队（数量不限）
- 当前活跃战队切换（`GET /api/teams/mine`、`POST /api/teams/{id}/activate`）
- 队长编辑战队简介（`PUT /api/teams/{id}`）
- 退队/被踢/解散后活跃战队自动回落

### 人才市场
- 已入队仍可申请其它战队、可发求职帖
- 招募帖对已在该队的用户不再显示申请按钮
- 入队审批不再连带作废其它队伍的待处理记录

### 认证
- 图片上传前自动压缩
- 按真实格式落盘（不再一律 `.png`）
- 上传失败给出可读原因

## 技术要点（面向开发）

| 场景 | 做法 |
|---|---|
| 多队归属 | `team_members` 本就无唯一约束，限制全在业务层，逐条放开即可 |
| 活跃战队 | `users.active_team_id`（nullable），读取时校验成员关系，失效则回落到最早加入且存续的队伍 |
| 多队下的 `canApply` | 从「是否属于任何战队」改为「是否已在该帖所属战队」 |
| 待处理记录去重 | 从「全局每人 1 条」改为「每支队伍 1 条」 |
| 图片后缀判定 | 先取 data URL 的 MIME，缺失或不认识时按文件头魔数兜底 |
| base64 容错 | `Base64.getMimeDecoder()` + 去空白，替代严格的 `getDecoder()` |

数据库变更：`users` 新增 `active_team_id`（`ddl-auto: update` 自动加列，无需手工迁移）。表数量不变，仍为 24 张。

## 注意事项 / 已知限制

1. **每人仍只能创建一支战队**。以队员身份加入的战队不限。真要做「一人多队队长」，得先把 `teams.captain_id` 拆成成员关系上的 `role`，属于结构性改造
2. **个人主页只展示活跃战队**。`UserVO.team` 是单值，多队用户的其它队伍需要到「我的战队」或战队页查看
3. **历史认证材料仍是 `.png` 后缀**。修复只影响新上传的文件，旧记录不动；如果旧图本身是 JPEG 且在某些浏览器显示异常，重新上传一次即可
4. **被 413 拦掉的历史申请不会自动补**。受影响的用户需要重新提交
5. **前端压缩上限 1600px**。用于学信网截图、段位截图足够；如果以后要传需要放大查看细节的材料，得单独放宽
